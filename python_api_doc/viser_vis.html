pymomentum.viser_vis

Viser Visualization Helpers

Helper functions for visualizing momentum characters in a viser web viewer, providing a live interactive 3D scene with per-frame updates.

Unlike the Rerun helpers (pymomentum.rerun_vis), viser is a live server — you add geometry once and then update transforms each frame. The typical usage pattern is:

import viser
import pymomentum.geometry as geo
from pymomentum.viser_vis import add_character, update_character

server = viser.ViserServer(host="::", port=8080)
character = geo.Character.load_urdf("robot.urdf")
skel_state = geo.joint_parameters_to_skeleton_state(character, joint_params)

handles = add_character(server, "character", character, skel_state)

# In your simulation loop:
for frame in frames:
    new_skel_state = geo.joint_parameters_to_skeleton_state(character, params)
    update_character(server, handles, character, new_skel_state)

Individual functions are also available:

  • add_mesh() / update_mesh() — manage a Mesh

  • add_skinned_mesh() / update_skinned_mesh() — upload mesh data once and update only bone transforms

  • add_joints() / update_joints() — manage skeleton joint frames

  • add_collision_geometry() / update_collision_geometry() — manage collision proxy capsules, ellipsoids, and boxes

  • add_character() / update_character() / remove_character() — manage a complete character

Mesh wireframe and collision proxy visibility are controlled through viser’s built-in scene-tree panel (each is its own scene node), so no bespoke GUI toggle is provided — a single control avoids the desync between a custom checkbox and the scene tree’s client-side visibility override.

GUI widget helpers (optional, for apps building interactive viewers):

  • add_character_param_sliders() — one slider per model parameter

  • add_log_panel() — scrollable HTML log strip (returns a LogPanel)

pymomentum.viser_vis.add_character(server: viser.ViserServer, entity_path: str, character: pymomentum.geometry.Character, skel_state: np.ndarray, *, posed_mesh: pymomentum.geometry.Mesh | None = None, use_skinned_mesh: bool = False, color: tuple[int, int, int] = (200, 200, 200), scale: float = 0.01, axes_length: float = 0.05, axes_radius: float = 0.002, collision_geometry: bool = False, collision_geometry_visible: bool = True) → CharacterHandles

Add a complete character visualization to the viser scene.

Creates joint frames and optionally a mesh, returning handles for subsequent updates via update_character().

  • {entity_path}/joints/{name} — per-joint coordinate frames

  • {entity_path}/mesh — posed or skinned mesh

  • {entity_path}/collision_proxies — collision capsules, ellipsoids, and boxes, if requested

Parameters:

  • server – The viser server instance.

  • entity_path – Root scene-graph path for the character.

  • character – The character to visualize.

  • skel_state – Skeleton state array of shape (n_joints, 8).

  • posed_mesh – An optional pre-posed mesh for the legacy mesh path. If None and use_skinned_mesh is false, no mesh is added.

  • use_skinned_mesh – If true and the character has a skinned mesh, add a client-side skinned mesh instead of uploading posed vertices.

  • color – RGB color tuple for the mesh.

  • axes_length – Length of joint axis indicators.

  • axes_radius – Radius of joint axis indicators.

  • collision_geometry – If true, add collision proxy capsules, ellipsoids, and boxes.

  • collision_geometry_visible – Initial visibility for collision proxies.

Returns:

A CharacterHandles for use with update_character().

pymomentum.viser_vis.add_character_param_sliders(server: viser.ViserServer, character: pymomentum.geometry.Character, *, on_change: Callable[[Any], None] | None = None, initial_values: np.ndarray | None = None) → list[Any]

Build one slider per model parameter of character.

Unbounded parameter limits are clamped via _normalize_param_limit() so the sliders stay usable. The caller reads slider values from the returned list (e.g. np.array([s.value for s in sliders])) and converts them back into model parameters.

Parameters:

  • server – The viser server instance.

  • character – The character whose model parameters drive the sliders.

  • on_change – Optional callback wired to every slider’s on_update event. The callback receives a single positional argument (the viser event object), which it can ignore.

  • initial_values – Optional length-n_params array of initial slider values. Each value is clamped to its slider’s range. If None, all sliders start at 0 (or the closest in-range value).

Returns:

The list of slider handles, in parameter-index order.

pymomentum.viser_vis.add_collision_geometry(server: viser.ViserServer, entity_path: str, character: pymomentum.geometry.Character, skel_state: np.ndarray, *, scale: float = 0.01, color: tuple[int, int, int] = (128, 64, 64), opacity: float = 0.45, visible: bool = True) → tuple[Any, list[_CollisionPrimitiveHandles]]

Add collision proxy primitives to the viser scene.

Momentum stores tapered capsules, ellipsoids, and boxes. Capsules are rendered as a cylinder plus two end icospheres using the larger endpoint radius (viser does not expose tapered capsules); ellipsoids are rendered as a scaled icosphere and boxes as a box mesh.

Parameters:

  • server – The viser server instance.

  • entity_path – Scene-graph path for the collision proxy group.

  • character – The character whose collision geometry is visualized.

  • skel_state – Skeleton state array of shape (n_joints, 8).

  • scale – Unit conversion factor. Defaults to CM_TO_M.

  • color – RGB color tuple for the collision proxies.

  • opacity – Material opacity for the proxies.

  • visible – Initial visibility for the collision proxy group.

Returns:

A tuple of (root_handle, collision primitive handle groups), one handle group per primitive in collision-geometry order.

Add per-joint coordinate frames and bone lines to the viser scene.

Each joint is rendered as a small set of RGB axes at its world-space position and orientation. Parent-child joints are connected by grey line segments.

Parameters:

  • server – The viser server instance.

  • entity_path – Base scene-graph path; joints are added as children.

  • character – The character whose skeleton is visualized.

  • skel_state – Skeleton state array of shape (n_joints, 8) with per-joint [tx, ty, tz, rx, ry, rz, rw, scale].

  • axes_length – Length of the axis indicators (in scene units).

  • axes_radius – Radius of the axis indicators.

  • bone_line_width – Width of the bone line segments.

  • bone_color – RGB color tuple for the bone lines.

Returns:

A tuple of (joint_handle_dict, bones_handle_or_None).

pymomentum.viser_vis.add_skinned_mesh(server: viser.ViserServer, entity_path: str, character: pymomentum.geometry.Character, skel_state: np.ndarray, *, color: tuple[int, int, int] = (200, 200, 200), scale: float = 0.01) → Any

Add a client-side skinned mesh to the viser scene.

Unlike add_mesh(), this sends rest vertices, faces, skin weights, and bind-pose bones once. Subsequent animation only needs update_skinned_mesh(), which updates per-joint bone transforms rather than re-uploading all posed vertex positions.

Parameters:

  • server – The viser server instance.

  • entity_path – Scene-graph path for the mesh node.

  • character – Character with a mesh, skin weights, and bind pose.

  • skel_state – Initial skeleton state array of shape (n_joints, 8).

  • color – RGB color tuple (r, g, b) in 0–255.

  • scale – Unit conversion factor applied to vertices and bone translations. Defaults to CM_TO_M.

Returns:

The viser skinned mesh handle. When per-vertex colors are present, returns a list of uniformly colored skinned submesh handles.

pymomentum.viser_vis.can_use_skinned_mesh(character: pymomentum.geometry.Character) → bool

Return whether Viser client-side skinning can represent character.

Viser uses at most four skinning influences per vertex. Characters with more influences should use the posed-vertex mesh path to preserve the original deformation.

Parameters:

character – Character to inspect.

Returns:

True if the character has a mesh and no vertex has more than four nonzero skin weights.

pymomentum.viser_vis.update_character(server: viser.ViserServer, handles: CharacterHandles, character: pymomentum.geometry.Character, skel_state: np.ndarray, *, posed_mesh: pymomentum.geometry.Mesh | None = None, scale: float = 0.01) → None

Update all character transforms in a single atomic batch.

Wraps updates in server.atomic() to avoid partial-frame rendering artifacts, following the pattern used in rl_robot’s viser renderer.

Parameters:

  • server – The viser server instance.

  • handles – The handles returned by add_character().

  • character – The character being updated.

  • skel_state – New skeleton state array of shape (n_joints, 8).

  • posed_mesh – If provided, updates mesh vertex positions.

  • scale – Unit conversion factor. Defaults to CM_TO_M.

pymomentum.viser_vis.update_collision_geometry(collision_handles: list[_CollisionPrimitiveHandles], character: pymomentum.geometry.Character, skel_state: np.ndarray, *, scale: float = 0.01) → None

Update collision proxy positions and sizes.

Always repositions every primitive from the current skel_state, regardless of visibility, so the proxies stay in sync with the model. Visibility is a separate concern controlled through viser’s scene-tree panel; gating updates on visibility would leave proxies stranded at a stale pose when later revealed through a path that does not re-run this.

Parameters:

  • collision_handles – Collision primitive handles returned by add_collision_geometry().

  • character – The character whose collision geometry is visualized.

  • skel_state – Skeleton state array of shape (n_joints, 8).

  • scale – Unit conversion factor. Defaults to CM_TO_M.

Returns:

None.
